## О проекте

Voice Router — проект голосового AI-робота для контакт-центра. Его задача — понимать запрос клиента в контексте разговора и выбирать подходящий сценарий через LLM, а не через энкодерный классификатор намерений.

Целевые пользователи:

- **Клиент контакт-центра:** говорит своими словами и получает голосовой ответ, в том числе при смене темы и языка.
- **Супервизор:** видит транскрипт, выбранные сценарии, обоснование, альтернативы и задержки обработки.

Предметная область стартового набора — вымышленная страховая компания **Saqta Insurance**. Компания, клиенты, продукты, цены и правила синтетические и не отражают реальное законодательство.

## Требования к решению

| Требование | Ожидаемое поведение |
|---|---|
| Голосовое взаимодействие | Микрофон и голосовой ответ в браузере; текст — резервный канал |
| LLM-маршрутизация | Выбор из 40 бизнес-сценариев и 3 системных намерений |
| Языки | Русский, казахский и смешанная речь |
| Контекст | Диалог до 10 реплик, обработка смены темы и нескольких намерений |
| Трассировка | После каждой реплики: транскрипт, сценарии, краткое обоснование, альтернативы и реальные задержки по этапам |
| Достоверность | Факты из базы знаний и мок-бэкенда организаторов, без выдуманных сведений |
| Безопасность действий | Необратимое действие — только после явного подтверждения клиента |
| Передача оператору | Если робот не справляется, разговор передаётся оператору |
| Воспроизводимость | Запуск одной командой и понятная инструкция проверки |

Системные намерения: `SYS_OUT_OF_SCOPE`, `SYS_UNCLEAR`, `SYS_GOODBYE`.

Выбор сценария через энкодерный intent-классификатор и хардкод сопоставления проверочных реплик со сценариями запрещены.

Ориентиры по скорости:

- **500 мс** на выбор сценария;
- **1,5 с** от окончания реплики клиента до начала голосового ответа.

Это бонусные ориентиры, **не условия сдачи и не достигнутые нами показатели**. Задержки необходимо измерять и отображать в интерфейсе.

## Ожидаемый пользовательский сценарий

Это описание целевого поведения, а не работающего демо:

1. Клиент разрешает доступ к микрофону и произносит запрос либо использует резервный текстовый ввод.
2. Решение получает текст реплики и выбирает сценарий через LLM с учётом контекста.
3. Панель трассировки показывает транскрипт, сценарии, обоснование, альтернативы и задержки.
4. При необходимости робот уточняет данные. Перед необратимым действием озвучивает их и получает явное подтверждение.
5. Клиент получает голосовой ответ на основе данных и результатов действий либо перевод на оператора.

## Как будет проверяться решение

После реализации планируется:

- проверить путь «микрофон → транскрипт → выбор сценария → голосовой ответ»;
- проверить русский, казахский и смешанную речь;
- проверить смену темы, несколько намерений, уточнение и передачу оператору;
- убедиться, что необратимые действия не выполняются без подтверждения;
- получить реальные предсказания на 104 dev-репликах и оценить их скриптом организаторов `evaluate.py`;
- сопоставить трассировку с фактическими действиями и измерить задержку до начала воспроизведения ответа.

`evaluate.py` оценивает основной сценарий, полное совпадение набора сценариев и полноту распознавания нескольких намерений. Он не заменяет проверку голосового взаимодействия и исполнения действий.

Сейчас эти проверки для проекта не выполнены. Скрипт оценки пока не включён в репозиторий. Предсказания и производные результаты должны сохраняться отдельно от исходного набора.

## Оценивание

Жюри проверяет маршрутизацию на **10 скрытых репликах**, включая казахский язык, смешанную речь, смену темы и пограничные случаи. Dev-набор предназначен для самопроверки и не заменяет скрытый набор.

Основной предмет оценки — качество маршрутизации. Скорость даёт дополнительные баллы; медленное решение не штрафуется.

README датасета уточняет проверку скрытого набора: за каждую реплику начисляется до 3 баллов — за правильный основной сценарий; за все сценарии при нескольких намерениях (в остальных случаях — за правильный язык ответа); за качество ответа с учётом данных.

Бонус за скорость определяется по медиане времени **от окончания речи клиента до начала воспроизведения ответа**: ≤ 1,5 с — 2 балла, свыше 1,5 с и ≤ 3 с — 1 балл, свыше 3 с — 0 баллов. Получение аудиофайла от TTS само по себе не означает начало воспроизведения. Жюри может выборочно проверить задержку секундомером. Замеров нашего решения пока нет.

5. Отправить последнюю версию проекта в GitHub-репозиторий команды, выданный платформой хакатона.

Пять часов — регламент инструкции, а не утверждение о текущем остатке времени. Обновление README или отправка коммита сами по себе не означают сдачу решения на платформе.

## Браузер и реальные провайдеры

- Оба провайдера проверены синтетическим PCM-входом до сценарного ядра и выходного аудио.
- После уточнения схемы SC40 выполнены четыре свежие текстовые Live-сессии. Все озвучки совпали с ответом ядра. Проверка выявила варианты отрицания, которые первоначально давали неправильный факт или `not_found`; исправления покрыты регрессиями на фактически полученных темах.
- Финальная браузерная проверка Gemini: «Объясните, что не покрывает КАСКО» → SC40 → `kb_lookup` → корректные исключения из KB → голосовой ответ и сохранённый транскрипт озвучки.
- Фактически озвученный текст хранится отдельно от проверенного ответа ядра. Это позволяет видеть расхождения и не приписывать модели неозвученный ответ.
- Широкий и узкий интерфейсы проверены; горизонтального переполнения нет. Логотипы загружаются, Noto Sans обслуживается локально. RU/KK glyph coverage проверен во всех трёх начертаниях.
- Физический микрофон участника, акустическое перебивание и медианная задержка по голосовому набору остаются ручными проверками. Их результат не выводится из синтетического smoke-теста.

## Воспроизведение

```sh
npm ci
npm test
python -X utf8 evaluation/evaluate.py docs/evaluation-predictions.json evaluation/dev_utterances.json
```

В приватном клоне выполните `docker compose --env-file .env.jury up --build -d --wait` с включённой конфигурацией жюри для запуска приложения с PostgreSQL. Реальные Live/API-проверки отдельно описаны в [README](../README.md) и расходуют квоту провайдера. HTTP health check сам по себе не доказывает работу микрофона, голосовой модели или внешнего доступа из любой сети.
